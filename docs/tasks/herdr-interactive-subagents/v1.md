# v1 — Interactive Pi subagents in Herdr (planned)

## Goal / current state

Regular `pi` runs in a Herdr-managed pane. `pi-subagents@0.71.0` already exists in the user's private Pi settings; it is a separate, non-pane-backed tool. The tmux-only `amosblomqvist/pi-interactive-subagents` v3.7.2 (commit `c3e8b53c0754ae5ccc19fdab5a7481ec039bc2f7`) reports unavailable when `HERDR_ENV=1` and `TMUX` is unset. `firstmate-pi` remains isolated and unchanged.

## Target / actions

- For ordinary Pi only, add a pinned/reviewable adaptation of the interactive subagents extension. Use separate `herdr_subagent`, `herdr_subagent_message`, `herdr_subagents_list`, and `/herdr-subagent` names to avoid colliding with the installed `pi-subagents` tool.
- Parent creates a sibling Herdr pane off its own `HERDR_PANE_ID` without changing focus; child runs a separate Pi process with an explicitly named JSONL session (Pi's conversation), in the same named Herdr session (terminal topology).
- Parent can steer a live child, receive its question and reply, receive completion asynchronously, and resume its Pi JSONL session by name after completion/restart. The original extension's agent allowlist and sandbox snapshot are preserved on resume.
- Missing Herdr environment/server/pane, failed shell launch, a vanished pane, missing sandbox snapshot or Pi session file, and an error exit return an actionable error rather than claiming success.

## Contracts (planned)

Spawn request: `{ "agent": "scout", "name": "auth", "task": "Review auth" }` → `{ "name": "auth", "pane": "w5:p…", "sessionFile": "…jsonl", "status": "started" }`. Child's Herdr pane and Pi JSONL file are distinct identifiers. Parent session ID keys the persisted name registry.

Steer/reply: `{ "name": "auth", "message": "Also check tokens" }` → live: prompt submitted to that pane; finished: new pane opens the *existing* Pi JSONL under the original tool/extension allowlist. Question event: `{ "name": "auth", "question": "…" }` → parent can reply using the same message tool. Completion event: `{ "name": "auth", "sessionFile": "…jsonl", "summary": "…", "exitCode": 0 }` is delivered to the parent as a steer message; no polling in the conversation.

## Boundary / out of scope

No Firstmate changes, automatic daemon start, macOS services, tmux emulation, shared Pi JSONL writers, migration of existing `pi-subagents` sessions, remote Herdr servers, or background terminal operation outside `HERDR_ENV=1`. Credentials, transcripts, shell launch scripts and name registry remain outside Git, in Pi's private session area.

## Acceptance and evidence

1. `node --test tests/herdr-interactive-subagents.test.ts` checks environment/quoting; `HERDR_LIVE_TEST=1` checks a real sibling pane, command, read, completion and cleanup without changing focus. Passed in Herdr 0.8.0.
2. `tests/pi-agent-fixture.sh` checks pinned Pi 1.0.2 RPC loading, GPT-6.1 Sol / low worker defaults, and Home Manager source; RPC in the current Pi also exposed both `herdr_subagent` and the older `subagent` without collision. Passed.
3. Model-backed smoke on Pi 0.86.1 verified spawn → child question → parent reply/steer → completion → resume by name on the same JSONL, including resume after a parent restart. It also exposed an upstream completion hint that triggered redundant resumes; the port removes that hint. Manual replies must still provide real tasks; a parent model can send redundant follow-ups if prompted to do so.
4. `nix flake check --no-build` and full `darwinConfigurations.macos.system` build passed. The host-policy gate in `scripts/check.sh` stops on macOS 27 (profile requires 26), before tests; no activation performed.

Before Home Manager activation, only the build artifact/explicit `-e` path was exercised; auto-discovery via the managed symlink was checked in a temporary symlink, not in the user's live `~/.pi` directory. A running child's watcher is not reattached after restarting the parent; resuming a still-open child's JSONL is blocked instead.
