## Implemented behavior

1. User opens a rendered local-file hyperlink using WezTerm's native mouse action, bypassing Herdr mouse capture when necessary.
2. WezTerm's `open-uri(window, pane, uri)` intercepts local file links only. Web links retain their normal behavior.
3. Absolute file targets preserve their identity and bypass Herdr snapshot/CWD lookup. For Herdr, relative links use the current visible layout's pane CWD only when all visible panes share that CWD, or the layout is zoomed to its focused pane. Multiple visible project CWDs are ambiguous: show a notification requesting pane zoom or an absolute file link. Never use `foreground_cwd` or a stale outer terminal CWD. Outside Herdr, use WezTerm's native pane CWD.
4. Existing files open in Rider for a .NET project/file, otherwise PhpStorm. No new IDE installation or global macOS file association is required.
5. Missing/ambiguous local targets or failed IDE launches produce an actionable notification; they must not silently open the wrong file or fall through to a browser.

## Contracts / failure boundary

- Verified WezTerm event: `(window, pane, uri: string)`; return `false` to suppress the system URL opener after handling a local link.
- Verified `herdr api snapshot` response fragment: `{ "result": { "snapshot": { "focused_workspace_id": "w5", "focused_tab_id": "w5:tB", "focused_pane_id": "w5:pY", "layouts": [{ "workspace_id": "w5", "tab_id": "w5:tB", "zoomed": false, "panes": [{ "pane_id": "w5:pY" }] }], "panes": [{ "pane_id": "w5:pY", "cwd": "/absolute/project", "foreground_cwd": "/possibly/transient/directory" }] } } }`.
- IDE invocation uses an argument array, not shell interpolation of link text. Percent encoding and spaces survive URL decoding.
- Out of scope: remote SSH paths, multiple simultaneous Herdr clients/named sessions, arbitrary relative links across visible different-project splits, installing IDEs, changing web-link behavior, wrappers around Pi, restarting existing Pi/Herdr sessions, and rewriting previous conversation text.
